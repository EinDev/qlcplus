# QLC+ 5 Refactoring Survey — prioritized findings

Read-only investigation across `qmlui/`, `engine/`, `qmlui/virtualconsole/`, and `qmlui/qml/`. No files modified. Categories: **P** = performance, **B** = bug-reduction, **R** = readability. Findings 1, 2, 4, 5, 7, 8, 17, 20, 22 verified first-hand; the rest verified by dedicated area reviews with confidence as stated.

## A. Hot-path performance (daily felt)

**1. Function Manager search rebuilds the tree once per item, per keystroke** — `qmlui\functionmanager.cpp` `updateFunctionsTree()` (~1804-1885), triggered per keystroke by `setSearchFilter()` (~199-213) — **P** — Exact same shape as the already-fixed FixtureManager keystroke bug: `clear()` + N×`addItem()`, each emitting `structureChanged`, each triggering a full `TreeFlatModel::rebuild()` (wired via `qml\fixturesfunctions\FunctionManager.qml:267`). With hundreds of functions that's O(n²) per keystroke. `ImportManager::updateFunctionsTree()` (`importmanager.cpp:789`) has the same gap. Fix: wrap in `setNotificationsSuspended(true/false)` + one explicit rebuild, exactly as `fixturemanager.cpp:934/980` now does. **Confidence: high.**

**2. `ContextManager::slotUniverseWritten` scans all fixtures and copies channel data per tick** — `qmlui\contextmanager.cpp:2586-2606` — **P** — Runs per universe per ~20ms tick during playback; iterates all ~120 fixtures each time (~720 iterations/tick at 6 universes) and builds a full `QByteArray` copy of every same-universe fixture's channels *before* knowing whether anything changed. Fix: per-universe fixture index (rebuilt on fixtureAdded/Removed); copy old values only when `setChannelValues` reports a change. **Confidence: high.**

**3. 2D/3D preview fan-out is ungated; 2D re-rasterizes a Canvas per moving head per frame** — `qmlui\mainview2d.cpp:416-470`, `qmlui\mainview3d.cpp:1402-1428`, `qml\fixturesfunctions\Fixture2DItem.qml:136-145, 232-286` — **P** — Both views fire per-head `QMetaObject::invokeMethod` for intensity/color every changed frame without comparing against the `previous` array they already receive. Worse: 2D sets `setPosition = true` whenever a Pan/Tilt channel merely *exists* (`mainview2d.cpp:460/469`) — 3D correctly gates on `value != previous.at(i)` — and `Fixture2DItem.setPosition()` ends in an unconditional `requestPaint()` that redraws both static curves and cursors. Fix: gate all channels on `previous` like 3D's pan/tilt; split the Canvas into a static layer + cursor layer (the pattern `EFXPreview.qml:66-71` already documents). The two views' near-duplicate 200+ line channel-scan switches (`mainview2d.cpp:376-609` vs `mainview3d.cpp:1354-1623`) are what let this drift happen — extracting a shared "decoded fixture frame" helper fixes the perf gap and the drift at once. **Confidence: high.**

**4. `GenericDMXSource::m_changed` is never cleared — full value-map rewalk every 20ms forever** — `engine\src\genericdmxsource.cpp:110` (set at 55/62/70, never reset; shadows dead `DMXSource::m_changed` accessors with zero callers) — **P/B** — Once any value is set, `writeDMX()` re-walks the whole map with a `doc->fixture()` lookup + locked fader update per value on every tick, even though the persistent fader keeps outputting on its own. Fix: clear the flag after processing and delete the shadowing member. *Caveat: the perpetual re-add currently masks GenericFader's auto-removal of HTP channels at zero (`genericfader.cpp:304-311`) — a held-at-0 channel needs a targeted test after the fix.* **Confidence: high.**

**5. `Scene::setValue` emits `changed` unconditionally — playing a Sequence floods the GUI thread and marks the project modified** — `engine\src\scene.cpp:168` — **P/B** — The emit fires even when `valChanged` is false and even on the `blind` path. `ChaserRunner::startNewStep` (`chaserrunner.cpp:570-577`) calls it once per stored value per step from the timer thread; each emission is queued to `Doc::slotFunctionChanged` → `setModified()`. User-visible symptom: merely playing a sequence flags unsaved changes and kicks autosave. Fix: emit only when `valChanged`, and skip on `blind`. **Confidence: high.**

**6. `VCXYPad::slotUniverseWritten` rebuilds QVariant maps per frame, even for hidden pads** — `qmlui\virtualconsole\vcxypad.cpp:1708-1811` (connected unconditionally at 138-139) — **P** — Every changed-universe tick, every XYPad (visible or not) re-resolves group head lists, per-head channel numbers, builds a `QVariantMap` per head, then deep-compares the list. Fix: connect/early-out on visibility; compare packed plain values and build the QML list only on change; cache resolved channels. **Confidence: high.**

**7. `TreeFlatModel::data()` does an O(siblings) `items().indexOf()` per call, per role** — `qmlui\treeflatmodel.cpp:174, 183, 198` — **P** — Called for every role of every delegate; after a rebuild + delegate re-creation this is effectively O(n²) for large flat lists. Fix: store the owner-row index in `FlatRow` (maintained by `rebuild()`/`reindexFrom()`, which already walk everything). **Confidence: high.**

## B. Threading and lifetime

**8. Undo/redo history is mutated from two threads with no lock** — `qmlui\tardis\tardis.cpp` `run()` (233-327) vs `undoAction()`/`redoAction()` (145-213); members at `tardis.h:366-376` — **B** — `run()` (worker thread) appends/trims/replaces `m_history` and writes `m_historyIndex`; undo/redo (GUI thread, from QML) read and rewind the same `QList` and index with only the queue mutex protecting the queue. Ctrl+Z while an action is being folded in is a data race on a non-atomic container. Fix: one mutex around history+index, or marshal undo/redo requests through the same queue the worker drains. **Confidence: high.**

**9. `ChaserRunner::slotChaserChanged` deletes running steps from the GUI thread without the runner mutex** — `engine\src\chaserrunner.cpp:94-120` — **B** — The runner lives on the GUI thread (`chaser.cpp:626`), so editor changes to a running chaser directly stop/delete `m_runnerSteps` entries while the timer thread iterates the same list under `Chaser::m_runnerMutex` (`chaser.cpp:668-675`) — a lock this slot never takes; every other GUI entry point does. Fix: set a dirty flag and do the surgery at the top of `write()`, the pattern the file already uses for `m_updateOverrideSpeeds`. (Rider: the slot also copies the full step list once per running step — O(n²).) **Confidence: high.**

**10. `VCCueList::setChaserID` connects where it should disconnect** — `qmlui\virtualconsole\vccuelist.cpp:483-484` — **B** — The "detach old chaser" block disconnects three signals but **connects** `stepChanged(int)` on the *old* chaser; the attach block also wires `stepChanged`/`stepsListChanged` that detach never removes. Re-attaching leaves the old chaser driving `slotStepChanged` (line 548, which has no `chaser()` null check) — wrong-model updates or a crash. Fix: mirror the connect/disconnect lists exactly; null-guard the slot. **Confidence: high.**

**11. `VCAudioTriggers` caches a raw `Function*` that dangles after deletion** — `qmlui\virtualconsole\vcaudiotriggers.cpp:637-645` (also 452, 937) — **B** — `AudioBar::m_function` is never invalidated; no `functionRemoved` handling exists in the file. Delete the attached function, and the next audio beat calls `start()` on freed memory. VCCueList already handles this case (`vccuelist.cpp:66`); VCButton/VCSlider resolve by ID. Fix: subscribe to `Doc::functionRemoved` or resolve per beat. **Confidence: high.**

**12. `VCSlider`'s level mutex is only taken on the DMX thread** — `qmlui\virtualconsole\vcslider.cpp:1262, 1416` (lock sites) vs `setValue` (466-506), `addLevelChannel`/`removeLevelChannel` (594-606), `slotTreeDataChanged` (767) — **B** — All UI-thread producers mutate `m_value`/`m_levelChannels` unlocked; line 767 even `std::sort`s the list `writeDMXLevel` may be iterating. One-sided mutex = overhead plus false confidence. Fix: lock the (rare) mutators too, or snapshot-under-lock. **Confidence: high.**

## C. Fragile coordinate/state math

**13. 2D drag delta caches are never invalidated** — `qmlui\contextmanager.cpp:1205-1226` (reads), 1175/1202 (only writers); `contextmanager.h:485-490` — **B** — The caches from commit `76ddb87d5` are seeded once and updated only by the push functions; `resetContexts()` and doc load never clear them, and no external DMX write invalidates them. After a Scene/Simple Desk/chaser writes the same channels, the next drag resumes from stale values and snaps; entries can even leak across loaded projects (fixture IDs restart at 0). Fix: clear both hashes in `resetContexts()` and invalidate per-fixture when `slotUniverseWritten` sees an un-pushed change on those channels — keep the cache itself (it fixes a real bug). **Confidence: high** (mechanism), medium (frequency).

**14. Side-view position math is dimensionally wrong in two places** — `qmlui\contextmanager.cpp:1130, 1133` and `qmlui\fixtureutils.cpp:249` vs `:135` — **B** — (a) `setFixturesOffset`'s side-view branches add `gridSize().y()` (an absolute extent in grid cells) into a relative millimeter delta on every flush — a long drag drifts the fixture steadily; the FrontView branch shows the intended `currPos.y() - y`. (b) `item3DPosition`/`item2DPosition` are not inverses for side views (missing `* gridUnits` mm factor and different axis extent), so a fixture added while in RightSideView gets a garbage Z. Fix: `currPos.y() - y` in both branches; reconcile the transform pair so round-tripping is exact. **Confidence: high / medium-high.**

**15. 2DView selection rectangle mixes viewport and content coordinate frames** — `qml\fixturesfunctions\2DView.qml:241` vs `:269-286` — **B** — `onPressed` stores positions minus `contentX/contentY`; the drag-direction classification compares raw content-frame coordinates against them (the size math just below *does* subtract — showing the omission is accidental). With the view scrolled, the rotated-rectangle state machine picks the wrong rotation → wrong selection. The ±90°/−180° rotation machinery exists only to represent "dragged up/left"; a min/max-normalized rect removes both the state machine and the bug. **Confidence: high.**

**16. Loop-abort instead of skip poisons whole-list passes (×2)** — `qmlui\mainview2d.cpp:82-84` (`setUniverseFilter`: one stale itemID `return`s, leaving all remaining fixtures with stale visibility) and `qmlui\virtualconsole\vcframe.cpp:540-541` (`addFunctions` Ctrl-branch: first non-chaser in a multi-drop aborts the whole drop) — **B** — Both should be `continue`. **Confidence: high.**

**17. `TreeModel` hands out `QModelIndex`es whose internalPointer is a stack local** — `qmlui\treemodel.cpp:97, 291, 314` — `createIndex(i, 0, &i)` stores the address of a loop/local variable; anything that later calls `internalPointer()` dereferences garbage. Harmless today only because nothing does. Fix: pass the `TreeModelItem*` (or nullptr). **B, confidence: medium-high.**

## D. Duplication that will drift (the ChannelToolLoader lesson)

**18. Popup edge-clamp math exists in three verbatim copies, and TimeEditTool placement is re-derived at ~10 call sites** — `qml\ChannelToolLoader.qml:40-60`, `qml\virtualconsole\VCAnimationItem.qml:64-84`, `qml\virtualconsole\VCSliderItem.qml:289-315`; `qml\TimeEditTool.qml:66-88` + callers (`ChaserWidget.qml:102` passes raw `.y` while `SceneEditor.qml:345`, `RGBMatrixEditor.qml:564`, `EFXEditor.qml:884`, `VCSpeedDialPresets.qml:109` each pre-subtract height themselves; `show()` clamps only the bottom edge, never x) — **B/R** — This is exactly the code path the recent wrong-edge bug lived in; a fix to one copy misses the others. Fix: one shared positioning helper (anchor item in → clamped point out); `TimeEditTool.show(anchorItem, ...)`. **Confidence: high.**

**19. `VCFrame` repeats the widget-creation block ~10× in each of three functions (~400 lines), and its hot paths use recursive `findChildren`** — `qmlui\virtualconsole\vcframe.cpp:227-396, 496-585, 1118-1292`; `findChildren<VCWidget*>()`-then-filter-direct-children at `:1009, 1037, 1065` (`applySubmasterValue` runs per slider-drag tick, O(all descendants); `:1017` uses `reinterpret_cast` + meaningless null check where `qobject_cast` is the local idiom) — **R/B/P** — The drift already produced finding 16b. Fix: a type→(constructor, default size) factory + shared register-and-render helper; iterate `children(false)` (already held in `m_pagesMap`) instead of `findChildren`. **Confidence: high.**

**20. The function-attach and fixture-tree/search patterns are re-implemented per widget class, each copy slightly different** — attach dance: `vcbutton.cpp:157-217`, `vcslider.cpp:948-1013`, `vccuelist.cpp:464-532` (its drift *is* finding 10); fixture tree + `SEARCH_MIN_CHARS` logic: `vcslider.cpp:618-670`, `vcxypad.cpp:859-875/1184-1202`, `vcaudiotriggers.cpp:677-724` (XYPad's copy skips the `roleChanged` connect); and `showmanager.cpp` repeats its show connect/disconnect triple at 3 sites (102-116, 448-450, 1244-1246) — **B/R** — These are the unfixed siblings of finding 1's pattern family. Fix: shared attach/detach helper in VCWidget; a small shared fixture-tree holder; a `ShowManager::setCurrentShow(Show*)` that all sites route through. **Confidence: high.**

**21. Drag-ghost setup and tree-delegate role wiring are copy-pasted and already diverging** — ghost block in `qml\fixturesfunctions\FixtureGroupFlatDelegate.qml:131-150`, `FunctionManagerFlatDelegate.qml:77-81`, `PaletteManager.qml:244-248` (all use the subtly-wrong `mapToItem(mainView, qItem.x, qItem.y)`) vs `qml\virtualconsole\VCWidgetsList.qml:147` (already drifted to the correct `(0,0)` form); role wiring: `qml\TreeNodeDelegate.qml:90-139` assigns `isCheckable` one-shot while `FixtureGroupFlatDelegate.qml:61-119` uses `Qt.binding` — updates propagate in one tree and silently not the other — **B/R** — Fix: one shared `startDragGhost()` helper; one shared role-wiring function (or `required property` delegates). **Confidence: high.**

**22. The `isBatchSelection` escape hatch is a duplicated layering violation in the generic models** — `qmlui\treemodel.cpp:460-472` and `qmlui\treeflatmodel.cpp:251-263` — **R/B** — A generic model does a string lookup of the global `contextManager` context property + `invokeMethod` on every `setData`/role change, and on the batch path silently skips `dataChanged` (views depend on an implicit later refresh). Fix: an explicit batch API on TreeModel (begin/end, with a final coalesced notify) set by ContextManager — removes the global lookup, the duplication, and the implicit contract. **Confidence: medium-high.**

## E. Smaller wins

**23. Committed `console.log` on the hottest interaction paths** — `qml\TreeNodeRow.qml:112, 148` (every tree-row drag start/finish/drop), `qml\fixturesfunctions\2DView.qml:233, 465` (every 2D press/release) — **P/R** — On Windows each goes through `OutputDebugString`. Fix: delete or gate. **Confidence: high.**

**24. stagewizard/ carries a private hardcoded palette across all 14 files** — `qml\stagewizard\*` (`"#0978FF"` ×20, `"#E94560"` ×15, `"#2A2A44"` ×11, …), while the rest of the app uses `UISettings`; same for the pan/tilt widget colors shared verbatim between `Fixture2DItem.qml:232-286` and `PositionTool.qml:298-315` — **R** — Fix: a `WizardTheme` singleton / new UISettings tokens. **Confidence: high.**

**25. `Universe::requestFaderPriority` is a dead API containing a latent bug** — `engine\src\universe.cpp:256-282` — **B/R** — Zero callers repo-wide, and when *lowering* below all existing faders it moves the fader but never stores the new priority, so the next insertion sorts against a stale value. Same "looks wired up, isn't" shape as the undo/redo dead action codes found earlier this session. Fix: delete it, or set priority unconditionally + add a caller-facing comment. **Confidence: high** (dead), medium-high (latent bug matters once used).

**Also noted (verified, lower priority):** `VCSlider` Click&Go color math computed every tick but consumed only on change (`vcslider.cpp:1266-1287`); `MainViewDMX::updateFixture` rebuilds a per-channel string `QVariantList` per changed frame + missing null guard in `setFixtureFlags` (`mainviewdmx.cpp:136-161`); `VCWidget::applyInputProfileSettings` can double-connect encoder input on remap — no `Qt::UniqueConnection` (`vcwidget.cpp:856-877`); `FixtureManager::fixturesMap()` is a getter with side effects that rebuilds and emits its own NOTIFY signal (`fixturemanager.cpp:1799-1864`); address→universe index hand-rolled with magic `512` at three sites plus an unreachable-but-wrong `pow(255, n)` max in `Universe::writeBlended` (`scene.cpp:730`, `rgbmatrix.cpp:1001`, `genericdmxsource.cpp:122`, `universe.cpp:1046-1062`).

*Housekeeping note, not a finding: the working tree currently carries uncommitted `[DEBUG_LOG]`/`dbg*` instrumentation in `TreeNodeRow.qml` and `2DView.qml` from the in-progress drag work — per the project's own rule it should be stripped before the next fix commit.*

## If you only do 3 things

1. **Batch `FunctionManager::updateFunctionsTree()`** (finding 1) — the proven pattern: its sibling measured ~4.5s per keystroke before the identical fix landed in FixtureManager, and the fix is a two-line wrap.
2. **Gate the per-tick preview fan-out** (findings 2+3) — with the user's real scene (~120 fixtures, 6 universes) this cluster runs hot continuously during playback; gating on `previous` and splitting the Fixture2DItem canvas removes most per-frame waste in one pass.
3. **Fix `Scene::setValue`'s unconditional emit** (finding 5) — a few lines that stop sequence playback from flooding the GUI thread and spuriously marking the project modified — a symptom the user can see today.
